# Support chat design

These documents are the design for the product. They say what the project is for, what it is supposed to do, how the agents share one goal, and how the system is shaped.

They include the decisions made after the first draft: a greeting asks how the person is before it names a concern, improvement in their own words eases that concern, a short “it’s worse” leaves room for something else, and Understanding matches the stored phrase and its three snippets.

Read them in this order:

1. [What this project shows](01-what-this-project-shows.md) — the goal, the audience, and the demo.
2. [Requirements](02-requirements.md) — what the chat must do, including the later greeting, easing, and follow-up rules.
3. [Agents](03-agents.md) — who does which job, and the messages they pass.
4. [Diagrams](04-architecture-diagrams.md) — context, containers, sequences, data, activity, and deployment.
